## 一句话定位

> **Glyph 是一个公司能免费铺给 500 名开发者、无需购买授权、无需法务审查的跨平台代码编辑器——又快、又轻、又美，任何 AI agent 都能插进来。**

## 为什么是现在（立项背景）

2026 年，AI 编码已是常态，而企业的版权合规意识同步抬升。常见误解需要先纠正（详见 [`../research/01-landscape.md`](../research/01-landscape.md)）：

- **Notepad++** 是 GPLv3，**完全免费**、公司可商用——但**只有 Windows**。
- **真正要花钱的是 Sublime Text**：个人版 $99（含 3 年更新），**企业必须按人头买订阅**（$50–65/席/年），且不能拿员工个人 license 顶公司用。
- **VS Code** 官方二进制是**专有 EULA + 应用市场锁定**（不是 MIT），公司采用即采用一个专有工具。

市场调研结论：当前编辑器分三大阵营，**没有一个**同时满足以下全部：

| 维度 | 重型 Electron（VS Code/VSCodium/Pulsar） | 原生/终端（Zed/Lapce/Helix/Neovim） | 极小可魔改（Lite XL/Micro/Notepad++） |
|---|---|---|---|
| 宽松许可证 OSS | ◐ 源码 MIT，官方包专有 | ◐ Zed=GPL/AGPL | ✅ |
| 公司零成本 | ✅ | ✅ | ✅ |
| 原生轻量（<50MB / <200MB RAM） | ❌ 150–300MB+ / GB 级 | ✅ | ✅ |
| 开箱即美 | ✅ | ◐ | ❌ 视觉陈旧 |
| 非模态、对大众友好 | ✅ | ❌ 多为强制模态 | ◐ |
| 开箱即用 LSP/Git | ✅ | ✅ | ❌ |
| 跨平台 | ✅ | ◐ | ❌ Notepad++ 仅 Windows |

**空白就在正中间**：Zed 最接近，但 GPL/AGPL + Rust 重 + 偏 AI 云 + 历史上 Mac 优先；Lapce 精神最契合，但不成熟、生态薄。

## 差异化三角

Glyph 的护城河由三根支柱构成，缺一不可：

```
            ⚡ 轻 · 快 · 美
           （核心编辑体验）
           /              \
          /                \
  🤖 Agent 宿主 ———————— ✍️ 写作级 MD + 插件生态
（任何 agent 插进来）      （Live Preview + 插件优先）
```

1. **⚡ 轻 · 快 · 美** —— 比 VS Code 轻一个数量级（目标 <15MB 安装 / <40MB 内存 / <500ms 冷启动），键入"感觉即时"，开箱即是 Zed/Nova 级的精致默认主题。这是地基，永不为其他支柱让步。
2. **🤖 Agent 宿主** —— 不自建大模型、不做云 agent 集群。押注两个开放标准：**MCP（客户端）** + **ACP（宿主）**，让 Claude Code / Codex / Copilot CLI 作为子进程在编辑器里运行。billing/法务都在用户与 agent 厂商之间，我们零模型开销。定位是「**最快、任何 agent 都能插进来的编辑器**」。
3. **✍️ 写作级 Markdown + 插件生态** —— Obsidian/Typora 式**实时预览（Live Preview）**作为旗舰内容创作能力；整个产品**插件优先**，核心功能（含 MD）dogfood 同一套扩展 API。生态护城河是调研中**排第一的长期风险**，必须从架构层就为它让路。

## 目标用户

- **主**：写代码的开发者（前后端、脚本、运维、数据），尤其是**受版权/合规约束、不能随便装 Sublime/VS Code 官方包的公司开发者**。
- **兼顾**：需要顺手编辑任意文本/配置/Markdown 文档的"重度文本用户"。
- **明确不优先**：Vim 死忠（我们默认非模态，提供可选 Vim 模式即可）、纯非技术办公用户。

## 商业模式（保持开放）

- **v1：纯开源**（许可证倾向 **MIT / Apache-2.0**——刻意避开 Zed 的 GPL/AGPL 在企业法务处可能引发的审查摩擦；尽管 GPL 内部使用其实无碍，但"宽松许可证"能消除采购阻力）。
- **后续可选付费**：面向团队/企业的增值（集中策略管理、私有插件市场、SSO、审计、托管同步等），**编辑器本体永远免费开源**。参考 Zed 的"编辑器开源 + 云服务收费"路径，但我们更克制。

## 非目标（YAGNI，明确不做）

- ❌ 不做完整 IDE（不与 VS Code 全家桶/JetBrains 正面拼功能广度）。
- ❌ v1 不自建/不托管前沿大模型，不做云端后台 agent 集群（资本密集、已饱和、偏离主线）。
- ❌ 不绑定捆绑 API key（默认 BYO-key + 本地模型）。
- ❌ 不追求 Typora 式"完全隐藏语法"的 contenteditable WYSIWYG（改走 source-of-truth 的 Live Preview，见 [`../adr/0002-markdown-live-preview.md`](../adr/0002-markdown-live-preview.md)）。
- ❌ 不为臆测需求提前建设；不写降级/兼容兜底逻辑——**失败就响亮地失败**。

## 成功的样子（北极星）

- 一家公司的 IT/法务能在**不买任何授权、不做专项法律评估**的前提下，把 Glyph 一键铺给全体开发者。
- 开发者打开它的第一感受是「**怎么这么快、这么好看**」，第二感受是「**我的 Claude Code / Codex 直接在里面跑**」。
- 写 README / 文档时，它比专门的 Markdown 应用还顺手。
