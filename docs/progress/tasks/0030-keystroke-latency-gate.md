# 任务 0030：键入延迟 CI 门禁（文档模型层）

- 状态：✅ 落地并过 `pnpm check`（CI 内随测试运行）
- 里程碑：M2 工程 · 负责人：Claude · 开工/收工：2026-06-04

## Why
「延迟即产品」是不可降高线,但此前只是文档承诺、无自动守卫。需把红线变成**可执行 CI 检查**,防止有人引入「每键扫全文」的 O(doc) 退化而无人察觉。

## How
`src/__tests__/editLatency.test.ts`:在 200 行与 50,000 行两种文档上各连续追加 4000 次单字符,比较**每次编辑平均耗时**。CodeMirror 增量事务下编辑成本与文档规模无关,故断言 `largeDoc < smallDoc * 8 + 0.5ms`。
- **用「大/小文档耗时比」而非绝对毫秒** → 对 CI 机器速度不敏感,只在数量级退化时失败(避免 flaky 红 build)。
- 含预热(抹平 JIT 抖动);本地连跑 3 次稳定(46–55ms 全过)。
- 纯 `@codemirror/state`(已是直接依赖),无需 DOM/显示。

## 验证
- ✅ 本地连跑 3 次稳定通过;`pnpm check` 全绿(46 前端测试)。
- ✅ 随 `pnpm test` 进 CI(ubuntu),无需显示环境。

## 边界(诚实标注)
- 本门禁覆盖**文档模型热路径**(CM 事务),**不含 React 渲染 / 浏览器绘制**。
- 真实「输入→上屏」端到端延迟仍需显示环境实测(Playwright/tauri-driver + performance 标记),见 PROGRESS「下一步」。
- 即便如此,它守住了最易退化、影响最大的一环:编辑操作必须与文档大小解耦。
